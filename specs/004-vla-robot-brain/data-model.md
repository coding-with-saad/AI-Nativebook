# Data Model: Module 4: Vision-Language-Action (VLA)

## Entities

### Voice Command
-   **Description**: Raw audio input captured from a human user.
-   **Attributes**:
    -   `audio_stream` (raw audio data)
    -   `timestamp` (time of capture)
    -   `source` (microphone, file, etc.)

### Transcription Service
-   **Description**: Software component responsible for converting `Voice Command` audio into `Text Command`.
-   **Attributes**:
    -   `model_name` (e.g., "Whisper-tiny", "Whisper-base")
    -   `language` (e.g., "en-US")
    -   `latency` (time taken for transcription)
    -   `accuracy` (word error rate)

### Text Command
-   **Description**: Transcribed natural language input derived from `Voice Command`.
-   **Attributes**:
    -   `text` (string of transcribed words)
    -   `confidence` (probability of correct transcription)
    -   `timestamp` (time of transcription)

### Action Mapping
-   **Description**: Logic that translates a `Text Command` into one or more low-level ROS 2 actions or a high-level task for the LLM.
-   **Attributes**:
    -   `command_patterns` (regex or keyword matching for known commands)
    -   `robot_actions` (list of executable ROS 2 actions)
    -   `parameters_extraction` (logic to extract parameters from text, e.g., "move forward by 1 meter")

### Large Language Model (LLM)
-   **Description**: AI model used for cognitive planning, task decomposition, and natural language understanding of complex `Text Commands`.
-   **Attributes**:
    -   `model_id` (e.g., "GPT-4", "Llama2-7B")
    -   `interface_type` (API, local inference)
    -   `context_window` (maximum tokens for input/output)
    -   `capabilities` (list of functions the LLM can "call" related to robot actions)

### LLM Prompt
-   **Description**: Structured input provided to the `LLM`, including the `Text Command`, `Humanoid Robot State`, and available robot `Robot Action Sequence` primitives.
-   **Attributes**:
    -   `system_message` (defines LLM's role)
    -   `user_query` (the high-level task)
    -   `context` (robot state, environment details, perception outputs)
    -   `tools_schema` (JSON schema of callable robot actions)

### Robot Action Sequence
-   **Description**: A series of low-level ROS 2 actions (e.g., `Twist` messages, `JointTrajectory` commands) generated by the `LLM` or `Action Mapping`.
-   **Attributes**:
    -   `actions` (ordered list of specific ROS 2 actions)
    -   `parameters` (values for each action, e.g., speed, joint angles)
    -   `status` (pending, executing, completed, failed)

### Humanoid Robot State
-   **Description**: Current pose, sensor readings, and internal status of the robot, used as context for `LLM` planning.
-   **Attributes**:
    -   `pose` (position and orientation)
    -   `joint_states` (angles, velocities, efforts of all joints)
    -   `battery_level`
    -   `mode` (e.g., "idle", "moving", "grasping")
    -   `perception_output` (from `Perception System`)

### Perception System
-   **Description**: (From Module 3) Provides environmental understanding (e.g., object detection, localization) which feeds into `Humanoid Robot State` and `LLM Prompt`.
-   **Attributes**:
    -   `object_detections` (list of detected objects, locations, classes)
    -   `map_data` (environmental map)
    -   `localization` (robot's pose within the map)
    -   `semantic_understanding` (higher-level interpretation of environment)
