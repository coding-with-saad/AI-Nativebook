# Research Phase 0: Docusaurus and ROS 2 Structure

## Docusaurus Setup

- **Decision**: Initialize Docusaurus 3.x using `npx create-docusaurus@latest website classic` in the repository root.
- **Rationale**: The `classic` template provides the standard documentation layout (docs, blog, pages) needed for the book. Initializing in a `website` subdirectory keeps the repository clean, separating the site engine from the example code (`code/`).
- **Alternatives considered**: Manually configuring webpack/React (too complex), using a different SSG like Hugo (Docusaurus is better optimized for versioned documentation).

## ROS 2 Python Package Structure

- **Decision**: Use the standard `ament_python` layout generated by `ros2 pkg create --build-type ament_python`.
  ```text
  ros2_basics_py/
  ├── package.xml
  ├── setup.py
  ├── setup.cfg
  ├── resource/
  │   └── ros2_basics_py
  ├── ros2_basics_py/
  │   ├── __init__.py
  │   └── node_files.py
  └── test/
      ├── test_copyright.py
      ├── test_flake8.py
      └── test_pep257.py
  ```
- **Rationale**: conform to ROS 2 build farm standards and enables easy `colcon build` and `colcon test` execution. The `test/` directory is critical for verifying code correctness (Constitution Principle III).
- **Alternatives considered**: Ad-hoc scripts without a package structure (rejected as it violates automation and verifiable accuracy principles).

## Referencing Code in Docusaurus

- **Decision**: Use Docusaurus [Code Block component](https://docusaurus.io/docs/markdown-features/code-blocks#importing-code-snippets) to import code from the parallel `code/` directory.
  ```markdown
  <!-- Docusaurus allows importing code snippets -->
  ```jsx title="my-component.jsx"
  import MyComponent from '@site/../code/module-1/ros2_basics_py/ros2_basics_py/simple_publisher.py';
  ```
  *(Note: This requires checking if standard markdown imports are supported or if a plugin is needed, but worst case we copy-paste with automation. Default decision is to symlink or configure Docusaurus `static` or use webpack resolution if needed, but for simplicity, we might just copy files during build or try the `@site` alias if paths permit.)*
  *Refined Decision*: Use simple code blocks for now, and investigate `docusaurus-plugin-remote-content` or similar if direct relative imports outside `website/` are blocked. For Phase 1, we will assume standard Markdown code blocks for simplicity or explicit file copies during the deploy pipeline.
- **Rationale**: Keeps the "single source of truth" in the runnable `code/` directory while displaying it in the `website/` docs.
- **Alternatives considered**: Manually hardcoding snippets (risk of divergence), Git submodules for code (too complex for a single monorepo).
